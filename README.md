# 게임 콜라보 대시보드

조사 중인 게임들의 콜라보 이력을 모아 한 페이지로 보는 도구입니다. 공식 뉴스에서 콜라보 공지를 찾아내는 **크롤러**, 사람이 확인해 정리한 **콜라보 데이터**, GitHub Pages에 올리는 **정적 대시보드**로 이루어져 있습니다.

대시보드는 한국어만 표시합니다. 원문이 일본어·영어인 공지는 Chrome 번역을 거쳐 수집하고, 빌드할 때 일본어가 섞이면 실패하도록 막아 두었습니다.

현재 등록된 게임은 젠레스 존 제로, 블루 아카이브, 원신, 붕괴: 스타레일 네 개이고, 콜라보 161건과 캠페인 2개가 들어 있습니다.

## 빠른 시작

```bash
npm install
```
```bash
npm run preview
```
`npm run preview`는 데이터를 빌드한 뒤 `http://localhost:4173`에 대시보드를 띄웁니다.

## 전체 흐름

```
① 크롤링          ② 검토·정리            ③ 빌드·배포
목록 API로 기사    후보에서 실제 콜라보만   콜라보 데이터를 한 파일로 묶고
전체를 훑어        골라 한국어로 정리       한국어 검증 후 Pages에 배포
키워드 후보 추출
  ↓                  ↓                      ↓
data/candidates/   data/collabs/          site/data/dashboard.json
data/decisions/    data/ips.json
```

크롤링과 판단을 나눈 이유는 두 가지입니다. 사이트 구조가 바뀌어 크롤러만 고쳐도 이미 확정한 데이터는 영향을 받지 않고, 다시 실행하면 새로 올라온 후보만 확인하면 됩니다.

## 폴더 구조

```
crawlers/
├─ lib/                  # 게임과 무관한 공통부
│  ├─ cli.mjs            # 실행 옵션 처리
│  ├─ keywords.mjs       # 한국어·일본어·영어 콜라보 키워드 매칭
│  ├─ text.mjs           # 본문 HTML을 검사용 텍스트로 변환
│  ├─ translate.mjs      # Chrome 번역 제어
│  └─ output.mjs         # JSON 저장, CSV, 날짜 변환
└─ games/zenless/        # 게임별 크롤러 (게임을 추가하면 폴더가 늘어남)

data/                    # git으로 관리하는 원본 데이터
├─ games.json            # 게임 목록
├─ ips.json              # 콜라보 상대 사전 (한국어 이름 + 원문 별칭)
├─ aliases/{게임}.json    # 추가로 찾을 이름 + 오탐을 내는 이름(ignore)
├─ candidates/{게임}.json # 크롤러가 뽑은 키워드 후보
├─ decisions/{게임}.json  # 후보별 판정 기록 (채택·제외·검토 필요)
└─ collabs/{게임}.json    # 확정된 콜라보 (대시보드의 원본)

scripts/                 # crawl(실행), build(빌드·검증), serve(미리보기)
site/                    # 대시보드 (외부 라이브러리 없는 정적 페이지)
raw/                     # 크롤링 중간 결과 (git 제외)
```

**공식 사이트만 보면 콜라보를 많이 놓칩니다.** 예를 들어 붕괴: 스타레일 × 포트나이트, 젠레스 × 포토그레이, 원신 × 맘스터치는 공식 사이트 뉴스에 없고 호요랩에만 있습니다. 호요랩 쪽 게시물 수가 공식 사이트의 7~10배입니다(스타레일 2,475건 대 329건). 게다가 호요랩은 `x-rpc-language`로 한국어 게시물을 그대로 주기 때문에 번역이 필요 없습니다.

원신과 붕괴: 스타레일은 같은 콘텐츠 API를 쓰기 때문에 실행부를 `crawlers/lib/hoyo-content.mjs`로 모았습니다. 게임별 크롤러에는 API 주소·채널 ID·기사 URL 규칙만 적습니다.

블루 아카이브 일본 기사 페이지는 직접 열면 본문이 렌더링되지 않습니다. 그래서 API로 받아 둔 본문을 임시 로컬 페이지로 띄워 번역합니다(`crawlers/lib/local-page.mjs`). API로만 본문을 주는 사이트에는 이 방식이 더 안정적입니다.

언어별로 올라오는 공지가 다릅니다. 예를 들어 야마하 콜라보는 일본어 사이트에만, 하이디라오 콜라보는 영어 사이트에만 있었습니다. 빠짐없이 모으려면 세 언어를 모두 실행해야 합니다(한 언어에 1분이 걸리지 않습니다).

```bash
npm run crawl -- --game zenless --locale ja-jp
```
```bash
npm run crawl -- --game zenless --locale en-us
```

### 동작 방식
1. **목록 API (브라우저 없음)**: 뉴스 페이지가 내부적으로 쓰는 API로 기사 원문(제목·본문)을 100건씩 받아 키워드로 후보를 고릅니다. 1,100여 건이 10초 정도면 끝납니다.
2. **후보만 번역 (브라우저)**: 후보 기사만 Chrome으로 열어 번역된 한국어 제목과 발췌를 얻습니다.

### 번역 처리
- 크롤링 전용 Chrome 프로필(`.chrome-profile/`)에 "한국어로 항상 번역"을 미리 기록해서 **자동으로 번역**됩니다.
- 젠레스 사이트는 첫 HTML에 본문도 `lang` 속성도 없어서 Chrome이 언어를 "알 수 없음"으로 판정합니다. 그래서 `declarePageLanguage`로 원문 언어를 미리 선언합니다. 이게 없으면 자동 번역도, "항상 번역" 설정도 동작하지 않습니다.
- 자동 번역이 안 되면 실행 시작 때 한 번만 "번역을 켜고 Enter"를 요청합니다.
- 번역이 끝나지 않은 기사는 **멈추지 않고** 건너뛰고 `raw/{게임}/{언어}/errors.json`에 기록합니다. 한 바퀴를 돈 뒤 새 탭에서 한 번 더 시도하고, 그래도 실패하면 다음 실행 때 자동으로 재시도합니다.
- 언제 중단해도 다시 실행하면 이어집니다. 목록은 API로 다시 받고, 이미 번역한 기사는 건너뜁니다.

### 옵션
| 옵션 | 기본값 | 설명 |
|---|---|---|
| `--game` | 전체 | 실행할 게임 (`data/games.json` 기준) |
| `--locale` | 젠레스 `en-us` / 그 외 `ko-kr` | 젠레스는 `ko-kr`·`ja-jp`·`en-us`, 블루 아카이브는 `ko-kr`·`ja-jp`, 원신·스타레일은 `ko-kr`·`ja-jp`·`zh-cn` |
| `--category` | 젠레스·원신·스타레일 `news,events` / 블루 아카이브(한) `notice,events,past` / 블루 아카이브(일) `events,notices` | `all`도 가능. 점검·패치 게시판은 기본에서 뺐습니다 |
| `--titles-only` | – | 블루 아카이브 한국어 전용. 본문 확인을 건너뛰고 제목만 봅니다 |
| `--max-pages` | 제한 없음 | 테스트용으로 API 페이지 수 제한 |
| `--delay-ms` | `1000` | 기사 사이 대기 시간 |
| `--fresh` | – | 진행 기록을 무시하고 처음부터 |
| `--output-dir` | `raw/{게임}/{언어}` | 결과 폴더 |

### 결과
- `data/candidates/{게임}.json`: 한국어 제목이 포함된 후보 목록
- `raw/{게임}/{언어}/candidates.csv`: 엑셀로 바로 볼 수 있는 후보 목록
- `raw/{게임}/{언어}/summary.json`: 기사 수, 후보 수, 번역 실패 수
- `raw/{게임}/{언어}/progress.json`: 이어하기용 기록

## 2. 검토·정리

후보에는 실제 콜라보가 아닌 기사도 섞입니다(캐릭터 생일 스토리, 웹 이벤트 경품 목록, 게임쇼 참가 공지 등). 또 같은 콜라보가 언어별로 3건씩 잡힙니다. 그래서 사람이 확인해 `data/collabs/{게임}.json`으로 정리합니다.

- **`data/decisions/{게임}.json`**: 후보 기사마다 `collab`(어느 콜라보인지) / `campaign` / `exclude`(사유 포함) / `review` 중 하나를 기록합니다. 다시 크롤링해도 새 후보만 보면 됩니다.
- **`data/aliases/{게임}.json`**: `terms`에는 추가로 찾을 이름을, `ignore`에는 게임 안의 고유명사와 겹쳐서 오탐을 내는 브랜드 이름을 적습니다(예: 스타레일에서 "갤럭시"는 게임 내 조직 「갤럭시 레인저」에 걸립니다). 이름 배열만 적어도 됩니다.
- **`data/ips.json`**: 콜라보 상대의 한국어 공식명과 원문 별칭을 모아 둡니다. 기계 번역이 "젠리스 존 제로"처럼 제각각이라 표기를 여기서 통일합니다.
- 정리를 마치면 `data/collabs/{게임}.json`의 `"reviewed"`를 `true`로 바꿉니다. `false`면 빌드할 때 경고가 나옵니다.

### 콜라보로 보는 기준
판단이 갈리는 유형이 반복해서 나와서 기준을 정해 두었습니다.

| 유형 | 처리 | 이유 |
|---|---|---|
| 플랫폼 크리에이터 인센티브·방송 시즌 (더우인·후야·샤오홍슈·빌리빌리·위챗) | 제외 | 버전마다 반복되는 마케팅 프로그램 |
| 구독 보상 (프라임 게이밍, 크런치롤, 유튜브 프리미엄) | 제외 | 구독자에게 인게임 재화를 주는 프로모션 |
| 스토어 한정 제품 (갤럭시 스토어, 구글 플레이 기프트카드) | 채택 | 콜라보 실물 제품·에디션이 나옴 |
| 완구·피규어 제작사 (알터·GSC·반다이·펀코 등) | 채택 | 상대 브랜드 이름으로 제품이 나감 |
| 애니메이션 제작사 (MAPPA, ufotable) | 채택 | 제작 파트너십을 콜라보 이력으로 봄 |
| 게임쇼 참가·공동 전시 | 제외 | 행사 참가이지 제휴가 아님 |
| 경품·약관에 브랜드 이름만 등장 | 제외 | 제휴가 아니라 상품 구매 |
| 2차 창작 가이드라인, 자체 OST·웹이벤트 | 제외 | 상대가 없음 |

같은 상대와 여러 번 했을 때는 **테마나 제품이 다르면 항목을 나누고, 같은 캠페인의 회차(1차·2차)면 하나로 묶고 `note`에 적습니다.** 예를 들어 원플러스는 휴대폰 에디션·이모티콘·에이스 시리즈를 각각 나누고, 에이스는 2·3·6T를 한 항목에 묶었습니다.

### 콜라보 데이터 형식
```json
{
  "id": "zenless--kyuramen",
  "ip": "kyuramen",
  "form": "식음료",
  "regions": ["미국"],
  "date": "2026-08-14",
  "campaign": "operation-yum-2026",
  "note": "미국 전 큐라멘 매장, 한정 굿즈",
  "articles": [
    { "locale": "en-us", "url": "https://...", "date": "2026-07-20" }
  ]
}
```
- **`date`는 하나만 둡니다.** 콜라보 시작일을 알면 시작일, 모르면 공지일입니다.
- **`form`**: 인게임 / 식음료 / 카페·팝업 / 굿즈·하드웨어 / 브랜드 / 음악 / 기타. 목록은 `scripts/build.mjs`의 `FORMS`에 있고, 순서가 대시보드의 색·이모지 순서와 같습니다.
- **`regions`**: 진행 지역을 한국어로 적습니다(한국, 일본, 미국, 전 지역 등).
- **`campaigns`**: 냠냠대작전처럼 여러 지역 콜라보를 묶는 상위 캠페인입니다.

## 3. 빌드·배포

```bash
npm run build
```
`data/`의 파일들을 `site/data/dashboard.json` 하나로 묶습니다. 이때 다음을 검사하고, 하나라도 어긋나면 **빌드가 실패**합니다.
- 표시용 텍스트에 일본어(가나)가 섞였는지 — 한글이 없는 텍스트는 경고만
- `form`이 정해진 7종인지, 날짜가 `YYYY-MM-DD`인지
- `ip`와 `campaign`이 실제로 존재하는지

원문 별칭처럼 대시보드에 나오면 안 되는 필드는 이 단계에서 빠집니다.

배포는 `main` 브랜치에 push하면 GitHub Actions가 빌드 후 Pages에 올립니다(`.github/workflows/deploy.yml`). 저장소 **Settings → Pages → Source**를 **GitHub Actions**로 설정해야 합니다. `site/data/`는 배포할 때 새로 만들어지므로 git에서는 제외되어 있습니다.

## 대시보드 (`site/`)

외부 라이브러리 없이 HTML·CSS·JS만 씁니다.

| 파일 | 역할 |
|---|---|
| `index.html` | 화면 구조와 접근성 이름 |
| `design-tokens.css` | 테마 색상, 글꼴, 공통 크기 |
| `style.css` | 레이아웃, 컴포넌트, 반응형 |
| `app.js` | 검색·필터·정렬, 타임라인, 분석, 테마 |

화면 구성은 상단 메뉴, 제목 구역과 요약 수치, 검색·필터, 타임라인(게임별 행 · 이모지 표식), 형태별·지역별·연도별 분석, 콜라보 목록입니다.

### 스타일은 `design.md`를 따릅니다
**CSS나 마크업을 고치기 전에 루트의 [design.md](design.md)를 먼저 읽으세요.** 색·간격·컴포넌트 규칙이 모두 거기에 있습니다. 요약하면 이렇습니다.

- 무채색 테마에 1px 테두리. 상시 그림자와 장식용 색은 쓰지 않습니다.
- 색은 하드코딩하지 않고 토큰(`--page`, `--surface`, `--ink`, `--accent`, `--form-1`~`--form-7`)을 씁니다.
- 선택 상태는 `aria-pressed="true"`와 반전 색으로 표시합니다.
- 분류는 색만으로 전달하지 않고 **이모지와 텍스트를 함께** 표시합니다(🎮 인게임, 🍔 식음료, ☕ 카페·팝업, 🎧 굿즈·하드웨어, 🏷️ 브랜드, 🎵 음악, 📌 기타).

문서에 없는 규칙을 새로 만들었다면 `design.md`에도 반영해 주세요.

## 게임 추가하기

1. `data/games.json`에 `{ "id": "...", "name": "한국어 게임명" }` 추가
2. `crawlers/games/{게임}/crawler.mjs` 작성 — 목록을 받아 `data/candidates/{게임}.json`에 후보를 쓰는 역할입니다. 젠레스 크롤러를 참고하고, 공통 기능은 `crawlers/lib/`를 씁니다.
3. 크롤링 → 검토 → `data/collabs/{게임}.json` 작성 → 빌드

## 유지보수 메모

- **원신 API 설정**은 뉴스 페이지 JS 번들에서 찾았습니다(2026-09-21 확인). 글로벌은 앱 `a1b1f9d3315447cc`·`iAppId=32`·채널 396(뉴스)/397(공지)/398(이벤트), 중국은 `act-api-takumi-static.mihoyo.com`의 앱 `16471662a82d418a`·`iAppId=43`·채널 719(최신)/721(공지)입니다. 바뀌면 번들에서 `content_v2_user`를 검색해 다시 찾으면 됩니다.
- **붕괴: 스타레일 API 설정**도 같은 방법으로 찾았습니다(2026-09-22 확인). 글로벌은 앱 `113fe6d3b4514cdd`이고 `iAppId`를 **쓰지 않습니다**. 채널은 248(전체)/249(뉴스)/250(공지)/251(이벤트)이고, 중국은 앱 `1963de8dc19e461c`·`iAppId=238`·채널 255(전체)/256(뉴스)/257(공지)/258(이벤트)입니다.
- **중국 쪽 접속은 이 사무실 네트워크에서 불안정합니다.** `ys.mihoyo.com` 본체는 자주 시간 초과가 나지만, 위 API 도메인은 정상입니다. 다만 연결에 8~9초가 걸릴 때가 있어 재시도를 8회까지 합니다.
- **사이트 구조가 바뀌면** 크롤러가 API 오류나 셀렉터 오류를 내고 멈춥니다. 목록 API 주소와 앱 ID는 뉴스 페이지의 `getContentList` 요청에서 다시 확인할 수 있습니다(`crawlers/games/zenless/crawler.mjs` 주석 참고). 카테고리 ID(뉴스 295, 공지 296, 이벤트 297)는 세 언어가 같습니다.
- **호요랩 리치 텍스트 게시물**은 본문이 `content`가 아니라 `structured_content`(Quill delta JSON)에 있습니다. `content`에는 언어 코드만 들어 있어서 `structuredText`로 파싱합니다. 이걸 안 하면 본문 키워드 검사가 통째로 비어 버립니다.
- **콜라보라는 말이 없는 공지**도 있습니다(예: "「카프카」와 「블레이드」, ≪포트나이트≫에 강하"). 그래서 `data/ips.json`에 등록된 상대 이름 전체를 별칭으로 함께 검색하고, 이렇게 걸린 후보는 `confidence: alias`로 따로 표시합니다.
- **번역이 안 되면** 먼저 Chrome 번역 팝업에서 원문 언어가 "알 수 없는 언어"로 뜨는지 확인하세요. 그렇다면 `declarePageLanguage` 쪽 문제입니다.
- **Puppeteer는 기본으로 Chrome 번역 기능을 끕니다.** `crawlers/lib/translate.mjs`의 `TRANSLATE_ARGS`로 다시 켜고 있습니다.
- **테스트**: `npm test` (키워드 매칭, HTML 변환, CSV, 날짜 변환)
- 이 저장소를 OneDrive 폴더 안에 두면 `node_modules` 동기화로 느려질 수 있습니다. 저장소는 OneDrive 밖에 두는 편이 낫습니다.
